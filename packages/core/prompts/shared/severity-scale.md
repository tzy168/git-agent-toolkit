# 严重度判定标准（review 用）

## ⛔ 阻断（blocker）
合并前必须修，否则不得合入：
- 正确性错误：逻辑与意图相反、边界条件崩溃、空值未防护导致的运行时异常
- 安全漏洞：注入、越权、明文密钥、不安全的依赖用法
- 数据丢失：不可逆的删除 / 覆盖、迁移不可回滚
- 并发问题：竞态、死锁、丢失更新

## ⚠️ 重要（major）
应当修，可在本 PR 或紧随的 follow-up：
- 错误处理缺失：吞异常、失败路径未处理
- 明显性能问题：循环内重复 IO、N+1 查询、大对象深拷贝
- API 误用、契约不一致（参数顺序 / 单位 / 可空性）
- 缺关键测试（核心路径零覆盖）

## ✦ 建议（minor）
质量改进，不卡合并：
- 命名 / 可读性、重复代码可提取
- 缺文档注释、魔法数字
- 非核心路径的测试缺口

## · 吹毛求疵（nit）
风格癖好，可忽略：
- 个人偏好的格式 / 顺序
- 更"优雅"的等价写法

判定原则：拿不准就降一级；只有能给出"会怎么坏"的具体场景才升一级。
